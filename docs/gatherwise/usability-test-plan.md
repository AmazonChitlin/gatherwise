# Gatherwise Usability Test Plan

## Goal

Run five lightweight moderated sessions against the public recruiter demo and the core event-planning flow.

## Participants

Recruit five participants across the provisional proto-personas:

1. First-time small-event organizer
2. Experienced organizer entering a new jurisdiction
3. Vendor or food operator joining someone else's event
4. Recruiter evaluating the Handshake project
5. Accessibility-focused participant or participant using assistive technology

## Session Rules

- Use only fictional demo scenarios or generic prompts.
- Do not collect names, personal event details, or contact information inside the product.
- Ask for consent before recording quotes.
- Treat accessibility observations as first-class findings, not side notes.

## Core Tasks

1. Explain what Gatherwise does after viewing the hero.
2. Choose the intake path that feels right for the scenario.
3. Review one AI-extracted fact and say whether it should be confirmed or edited.
4. Find why a requirement may apply.
5. Open the official source for one result.
6. Identify one missing detail that could change the result.
7. Use the Event Change Simulator and describe what changed.
8. Explain what AI does and does not decide in the product.

## Data To Collect

- Task completion
- Time to first useful answer
- Misinterpretations
- Confidence in evidence
- Confusion points
- Quotes with consent
- Accessibility observations

## Success Signals

- Participants can explain the product within 90 seconds.
- Participants find the right path without hesitating between multiple equal starts.
- Participants can point to the official source and the Evidence Trail without coaching.
- Participants understand that the simulator diff is deterministic, not invented by AI.

## Post-Session Rhythm

1. Fill the test-session template.
2. Run a same-day debrief using the debrief template.
3. Cluster findings in the affinity map.
4. Update hypotheses and assumptions.
5. Add or revise items in the UX debt register.
