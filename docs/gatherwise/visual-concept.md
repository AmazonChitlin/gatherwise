# Gatherwise Visual Concept

Date: 2026-07-13
Route: `/dev/gatherwise-concepts`
Status: development-only concept exploration

## Core Direction

Gatherwise should feel like:

- civic wayfinding
- independent event production
- evidence-backed planning
- local route guidance

This is not a government portal, not a flashy AI dashboard, and not a generic startup card grid.

## Conceptual Inputs

Gatherwise can borrow abstract qualities from:

- transit and trail maps
- venue credentials and event passes
- production call sheets
- local wayfinding signs
- evidence tabs
- route markers
- stamped source records
- layered planning notes

These references should influence structure, rhythm, labeling, and trust cues without imitating any specific public agency, transit authority, or copyrighted identity.

## Desired Experience

Within the first 10-90 seconds, the interface should communicate:

- what the product does
- what kind of event facts matter
- how results connect to route logic
- where evidence comes from
- what is still unresolved

The visual system should make uncertainty actionable instead of making the product feel vague.

## Visual Strategy

- Use route logic as a structural device, not decorative illustration.
- Make evidence visible as a first-class object.
- Treat status as a shape-plus-label system, not just a color system.
- Use a subtle local grid for spatial rhythm and orientation.
- Keep layouts behaviorally familiar even when the styling is distinctive.

## Three Concept Directions

### 1. Route Ledger

- Character: structured, directional, analytical
- Inspiration emphasis: transit route boards, call sheets, evidence ledgers
- Strengths:
  - strongest explanation of cause-and-effect
  - easiest to connect facts, route stops, and evidence anchors
  - good fit for comparison and route comprehension work
- Risks:
  - can feel too operational if the tone gets cold
  - needs warmth in copy and spacing to avoid reading like an internal tool

### 2. Local Signal

- Character: bold, quick, highly legible
- Inspiration emphasis: wayfinding signs, venue signals, marker systems
- Strengths:
  - best first-glance clarity
  - strong mobile scannability
  - likely easiest for message-comprehension tests
- Risks:
  - could oversimplify nuanced evidence states
  - may feel more like signage than explanation if overused

### 3. Field Guide

- Character: human, documented, provenance-rich
- Inspiration emphasis: stamped records, planning notes, clipped passes
- Strengths:
  - strongest trust and provenance mood
  - supports manual fallback story well
  - may feel approachable for uncertain users
- Risks:
  - can drift into scrapbook noise if not kept disciplined
  - route logic may feel softer and less immediate

## Signature Motifs

Keep the motif system small. Use no more than these four recurring motifs:

### Route line

- Purpose: connect facts, decisions, requirements, and sources
- Use in: route summaries, progress indicators, comparison states

### Evidence tab

- Purpose: expose provenance and source state without requiring a drill-down first
- Use in: source cards, rule explanations, recruiter architecture proofs

### Status marker

- Purpose: communicate state with shape, icon, and text together
- Use in: requirement cards, warnings, unsupported states, source trust states

### Local grid

- Purpose: provide quiet compositional rhythm tied to orientation and planning
- Use in: backgrounds, concept sections, map-like rhythm behind key regions

## Familiar Interaction Anchors To Preserve

Even with a distinctive visual system, the product should keep standard behavior for:

- top-level navigation
- buttons
- forms
- dialog behavior
- links
- tabs
- breadcrumbs
- focus states
- mobile menus

The concept route intentionally keeps these conventional while changing surface language and visual rhythm.

## Anti-Patterns

Do not use:

- sparkle-heavy AI branding
- neon cyberpunk gradients
- government-seal imitation
- generic glassmorphism everywhere
- random floating blobs
- decorative maps with no meaning
- auto-rotating hero carousels
- horizontal page scrolling
- hidden navigation
- excessive card grids
- giant empty hero sections
- more than one dominant CTA per view
- status conveyed only by red, amber, and green

## Recommendation

Recommended direction for Prompt 4 exploration: `Route Ledger`

Why this is the current best lead:

- It best supports Hypothesis H5 by visually separating facts, rule results, and source evidence.
- It best supports Hypothesis H7 by making route logic legible without requiring extra explanation.
- It supports Outcome 3 by helping users explain why a requirement appeared.
- It supports Outcome 4 because the same route-and-evidence logic can help recruiters grasp the hybrid architecture quickly.

Why this is not a final decision:

- `Local Signal` may outperform it in 10-second message clarity tests.
- `Field Guide` may outperform it in trust and provenance testing.
- Paul should review all three before a final direction is chosen.
