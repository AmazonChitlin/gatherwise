# Gatherwise Hypotheses

Date: 2026-07-13
Primary hypothesis count: 8

## H1

We believe that first-time small-event organizers will achieve a useful source-backed summary without understanding municipal terminology if Gatherwise translates event facts into plain-language readiness guidance with visible official sources because novice users need interpretation, not government vocabulary. We will know this is true when most test participants can describe next steps and cite at least one supporting source without facilitator translation.

## H2

We believe that first-time small-event organizers will identify which missing event details may change the result if Gatherwise explicitly marks unresolved facts and shows their effect on certainty or route branching because uncertainty is easier to act on when it is named. We will know this is true when participants can name at least one missing fact and explain why it matters.

## H3

We believe that experienced organizers entering a new jurisdiction will achieve faster orientation if Gatherwise emphasizes jurisdiction-specific differences and evidence anchors instead of repeating generic checklist content because experienced users mainly need change detection. We will know this is true when participants can accurately explain what is locally different and what source supports that difference.

## H4

We believe that vendors or food operators joining someone else’s event will achieve better role clarity if Gatherwise separates organizer-controlled facts from participant-controlled facts because shared-event responsibility is often ambiguous. We will know this is true when participants can distinguish what they personally need to confirm from what depends on the organizer.

## H5

We believe that users will trust the product more if Gatherwise visibly distinguishes user-provided facts, AI-extracted facts, deterministic rule results, and official sources because trust breaks when inference layers are hidden. We will know this is true when participants can correctly label each evidence type and avoid calling inferred content “official.”

## H6

We believe that users will still achieve meaningful readiness progress if Gatherwise preserves a manual structured path when AI is unavailable because reliability matters more than novelty in high-uncertainty planning tasks. We will know this is true when participants complete a manual path and still report the result as useful for next-step planning.

## H7

We believe that users will explain why a requirement appeared more accurately if Gatherwise uses a Readiness Route metaphor with route stops, forks, and evidence anchors because causal structure is easier to grasp visually than as a flat list. We will know this is true when participants can interpret the path without instruction and correctly explain what triggered a route stop.

## H8

We believe that recruiters evaluating the Handshake project will understand Paul’s contribution and the hybrid architecture within 90 seconds if Gatherwise presents a concise architecture story with an explicit AI boundary and manual fallback because reviewers need fast orientation and credible scope boundaries. We will know this is true when recruiters can accurately describe the system layers and Paul’s role after a short review.
